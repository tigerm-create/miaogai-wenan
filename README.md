# 秒改文案

我是一个 UX 设计师。工作中天天要写按钮、报错、空状态、推送这些小文案，经常写完自己读一遍都觉得别扭——每个字都对，连起来就是不顺。

所以我做了这个小东西。把苹果和宜家中国官网的文案扒了一遍，又对照了苹果、谷歌、微软、宜家、Mailchimp 六份官方写作规范，提炼成一套改写方法。你丢一段原文进来，它给你三样：改写版、备选版，以及每处为什么这样改（这个最重要，下次你自己就会改了）。

## 举几个例子

原文：使用电子设备时请勿外放声音
改成：调低音量，互不打扰
为什么：原来想写"戴耳机"，但不是人人都有耳机。只约束结果（别吵到人），不规定手段。

原文：本次更新优化了产品体验并修复了若干已知问题
改成：启动更快了，闪退的老毛病也修了
为什么："优化体验"这种词等于没说，翻译成体感用户才懂。

原文：Meet Siri AI. / Your AI assistant. / More personal. / More powerful.
结论：这句不用改。
有意思吧——我拿苹果官网原文去考它，它没硬改，而是诚实地说不用改。行，诚实是好事。

## 怎么用

把 `秒改文案-发包版.md` 这个文件全文发给你的 AI（Claude、ChatGPT、国产的都行），然后说"按这个方法帮我改文案"，再贴上原文。就这么简单。

用 Muse 的话，把 `SKILL.md` 和 `skill.yaml` 放进 `custom-skills/copy-polish/` 目录，就能当原生 skill 使。

## 它按这 8 条规矩改

1. 一眼读完：按钮 2–6 个字，单行提示 15 字以内
2. 说该做什么，不说不许做什么
3. 不替用户做假设：只约束结果，不规定手段
4. 温度靠选词不靠字数："护好手指"比"小心夹手"暖，字数一样
5. "请""简单""只需"这类词默认删掉
6. 报错就讲两件事：出了什么问题、怎么办，不道歉不甩锅
7. 行业词原样保留（比如物流的"妥投"），只改周围的表达
8. 原文已经够好就直说不用改，不硬改

## 文件都在这儿

- `秒改文案-发包版.md`：单文件版，转发给朋友、发给任意 AI 即用
- `SKILL.md` + `skill.yaml`：Muse 原生 skill 格式
- `测试案例.md`：10 个真实案例，覆盖 10 种常见毛病
